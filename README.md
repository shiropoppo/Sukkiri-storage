# すっきり容量整理

クラウド（Google ドライブ / OneDrive）に**まったく同じ中身で保存されている**写真・動画を見つけて、パソコンやスマホから安全に削除し、空き容量を増やすツールです。

- まだクラウドにないものは、空き容量を確かめてからクラウドに保存（アップロード）できます。
- 名前はちがうけど中身が同じ写真・動画（`IMG_0001 (1).jpg` や LINE で保存しなおしたものなど）を見つけて、1つにまとめられます。
- いくつものフォルダに ✓ を付けて、まとめてしらべられます（前回選んだ場所は覚えています）。
- 時間がかかる作業の前には「充電器をつないでください」と案内し、つなぐと自動で始まります。作業中は画面やパソコンが眠らないようにし、電池がなくなりそうなら安全なところで止めます。
- 一度しらべたファイルは覚えておくので、途中で止まっても次は早く進みます。残り時間の目安も表示します。
- Google フォト・iCloud 写真をお使いの方には、それぞれの公式機能（「空き容量を増やす」「iPhone のストレージを最適化」）の手順を、大きな文字で案内します。
- 画面はブラウザで開きます。大きな文字・少ないボタンで、迷わず使えるようにしています。

---

## 安全のしくみ

「間違って大事な写真を消さない」ことを一番に作っています。

| しくみ | 内容 |
|---|---|
| 中身で照合 | ファイル名ではなく、**中身の指紋（ハッシュ）** で照合します。Google ドライブは MD5、OneDrive は QuickXorHash。名前がちがっても、中身が同じなら見つけられます。 |
| 削除の直前にもう一度 | 削除する直前に、クラウドの一覧を取り直し、手元のファイルの指紋も計算し直します。1つでも合わなければ消しません。 |
| 重複は全バイト比較 | 名前ちがいの重複を消すときは、残すファイルと**最初から最後まで1バイトずつ**見比べてから消します。 |
| 同期フォルダは扱わない | OneDrive・Google ドライブ・Dropbox・iCloud・Box と同期しているフォルダは選べません（ここで消すとクラウドからも消えてしまうため）。 |
| ゴミ箱へ | Windows ではゴミ箱に移すだけです。ゴミ箱を空にするまでは元に戻せます。 |
| 確認してから | 削除の前に「確認しました」にチェックを入れないと、削除ボタンが押せません。残したい写真は1枚ずつ外せます。 |
| 記録を残す | 削除したもの・保存したものは一覧表（CSV）に記録します（Windows はツールの `記録` フォルダ）。 |
| ログインは公式画面 | パスワードはツールに届きません。ログインは Google・Microsoft の公式画面で行い、ログイン情報はブラウザを閉じると消えます。 |

## 使い方（使う方向け）

### Windows パソコン

1. 受け取った ZIP ファイルを右クリック →「すべて展開」。
2. 展開したフォルダの **「はじめる（ダブルクリック）」** をダブルクリック。
   - 「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」。
3. ブラウザに画面が出たら、あとは画面の案内どおりに進みます。
   1. クラウドにつなぐ（ログイン）
   2. しらべる場所に ✓ を付けて「しらべる」（ピクチャ・ビデオなど。いくつでも選べます）
   3. 結果を見て「確かめて削除へ進む」
4. 削除したものはゴミ箱に入ります。**ゴミ箱を空にすると容量が空きます。**

画面を閉じると、裏で動いている部分も数分で自動的に終わります。

### Android スマホ（Chrome）

1. 設定した方から教わったアドレス（`https://…`）を Chrome で開きます。メニューの「ホーム画面に追加」をしておくと便利です。
2. クラウドにつなぎ、「フォルダを追加」で **DCIM → Camera** などを選んで「許可」を押します（いくつでも追加できます）。
3. 「充電器をつないでください」と出たら、充電器をつなぐと自動で始まります。終わるまで画面はそのままにしてください。
4. Android では削除したものはゴミ箱に入らず、すぐ消えます（クラウドに同じものがあることは確認ずみです）。

写真を **Google フォト** にバックアップしている場合は、最初の画面の「Google フォト」を押すと、Google フォトの「空き容量を増やす」の手順と、アプリを開くボタンが出ます。

※ 古い Chrome などフォルダを選べない場合は、iPhone と同じ「写真を選んで調べる」方式になります。

### iPhone

1. 設定した方から教わったアドレスを Safari で開きます。
2. クラウドにつなぎ、「写真・動画を選ぶ」で調べたい写真を選びます。
3. iPhone の仕組み上、**ツールから直接は削除できません。** 結果の一覧を見ながら、「写真」アプリで削除してください（手順も画面に出ます）。

---

### Android アプリ（おすすめ・全部おまかせ）

`android` フォルダが Android 用のアプリです。写真を1枚ずつ選ぶ必要はなく、次のことを自動で行います。

1. スマホの写真・動画を**全部**しらべ、中身の指紋（MD5）で Google ドライブと照らし合わせる
2. まだクラウドにないものを、空き容量を確かめてから**自動で保存**する（保存後に中身が同じか確かめる）
3. **クラウドの中の重複**（大きさ・MD5・SHA-256 がすべて同じ写真・動画）を1つ残してドライブのゴミ箱へ
4. 「スマホから消して空ける」を押すと、保存ずみのものを最終確認してから、スマホのゴミ箱へ移す（30日間は戻せる）

「毎晩、充電中・Wi-Fi のときに自動で整理する」をオンにしておくと、1〜3 は夜のうちに自動で進み、消せるものが見つかると通知でお知らせします。

**インストール**：`android/dist/sukkiri-yoryo.apk` をスマホに送り（LINE や Google ドライブなど）、開いてインストールします。初回だけ「提供元不明のアプリ」を許可する操作が必要です。

**作り直すとき**：`pwsh android/build-apk.ps1`（Java 21・Android SDK は `%LOCALAPPDATA%\SukkiriBuild` と `%LOCALAPPDATA%\Android\Sdk` に入っています）。
`android/keystore`（署名鍵）は**なくすと更新版を作れなくなる**ので、必ず別の場所にもバックアップしてください（GitHub には上げていません）。

## 設定のしかた（配る方向け・最初に一度だけ）

Google・Microsoft にログインしてもらうために、「このツールを使ってよい」という登録が必要です。どちらか片方だけでも使えます（使わない方は空欄のまま）。

設定が終わっていない状態でツールを開くと、**登録するときに入力する値**が画面に表示されます。

### 1. Google ドライブ用の登録

1. [Google Cloud コンソール](https://console.cloud.google.com/) で新しいプロジェクトを作ります。
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を有効にします。
3. 「Google Auth Platform」（OAuth 同意画面）を設定します。
   - アプリ名：`すっきり容量整理`、対象：**外部**
   - データアクセス（スコープ）に次の 2 つを追加
     - `https://www.googleapis.com/auth/drive.metadata.readonly`（ファイル情報の参照）
     - `https://www.googleapis.com/auth/drive.file`（このツールで保存するファイルの作成）
   - 「対象」→ **テストユーザー** に、使う方の Gmail アドレスを追加します（100 人まで）。
4. 「クライアント」→「クライアントを作成」→ 種類 **ウェブ アプリケーション**。
   - **承認済みの JavaScript 生成元** に追加：
     - `http://localhost:8765`（Windows 用）
     - スマホ用に公開する場合は、その URL の先頭部分（例：`https://yourname.github.io`）
5. 表示された **クライアント ID** を `app/config.js` の `googleClientId` に貼り付けます。
6. Android アプリを使う場合は、もう1つ「クライアント」を作ります。種類 **Android**、パッケージ名 `io.github.shiropoppo.sukkiri`、SHA-1 は署名鍵の指紋（`keytool -list -v -keystore android/keystore/sukkiri.jks -alias sukkiri` で確認）。
   また「データアクセス」に `https://www.googleapis.com/auth/drive`（ドライブのすべてのファイル。クラウド内の重複整理に使う）を追加します。

> ログインのとき「このアプリは Google で確認されていません」と表示されます（個人で使うアプリのため）。テストユーザーに登録した方は「続行」を押せば使えます。
> テストユーザーに登録していないアカウントを選ぶと「アクセスをブロック … エラー 403: access_denied」と表示されます。スマホにふだんログインしているアカウントが、登録したものと違うことがよくあるので、アカウントを選ぶ画面で確かめてください。

### 2. OneDrive 用の登録

> **個人の Microsoft アカウントだけでは登録できません。** 「ディレクトリ（テナント）の外でアプリを作る機能は廃止」となっているため、先に [Azure の無料アカウント](https://azure.microsoft.com/ja-jp/free/) を作るなどして、ディレクトリを用意してください（本人確認でカードの入力が求められます）。会社・学校の Microsoft 365 をお使いなら、そのディレクトリで登録できます。

1. [Microsoft Entra 管理センター](https://entra.microsoft.com/)（または Azure ポータル）→「アプリの登録」→「新規登録」。
   - 名前：`すっきり容量整理`
   - サポートされているアカウントの種類：**個人用 Microsoft アカウントのみ**（会社・学校のアカウントも使うなら「任意の組織ディレクトリ内のアカウントと個人用 Microsoft アカウント」）
   - リダイレクト URI：プラットフォーム **シングルページ アプリケーション (SPA)**、`http://localhost:8765/`
2. 「認証」で、スマホ用に公開する場合はその URL（例：`https://yourname.github.io/sukkiri/`）も SPA のリダイレクト URI に追加します。
3. 「API のアクセス許可」→ Microsoft Graph →「委任されたアクセス許可」で `Files.ReadWrite`、`User.Read`、`offline_access` を追加します。
4. 「概要」の **アプリケーション (クライアント) ID** を `app/config.js` の `microsoftClientId` に貼り付けます。
   - 会社・学校のアカウントも使う場合は `microsoftTenant` を `'common'` にします。

### 3. スマホでも使えるようにする（公開）

スマホではファイルを直接動かせないため、`app` フォルダの中身を **https のアドレス**で公開します。このリポジトリ（`shiropoppo/Sukkiri-storage`）には、GitHub Pages で自動公開する設定（`.github/workflows/pages.yml`）が入っています。

1. リポジトリの「Settings」→「Pages」→「Build and deployment」の Source を **GitHub Actions** にします（最初の一度だけ）。
2. `main` に保存（push）すると、`app` フォルダの中身が `https://shiropoppo.github.io/Sukkiri-storage/` に公開されます。
3. Google Cloud の OAuth クライアントに、次の2つを登録します（Microsoft を使う場合は、Microsoft 側のリダイレクト URI にも上のアドレスそのものを追加）。
   - 「承認済みの JavaScript 生成元」：`https://shiropoppo.github.io`（パソコンのポップアップ式ログイン用）
   - 「承認済みのリダイレクト URI」：`https://shiropoppo.github.io/Sukkiri-storage/` と `http://localhost:8765/`（スマホは、ポップアップではなくページごとログイン画面へ移る方式を使うため）
4. 使う方の Gmail アドレスをテストユーザーに追加し、アドレスを伝えます（QR コードにすると渡しやすいです）。

`記録` フォルダ（削除・保存の記録）は `.gitignore` で公開対象から外しています。`config.js` のクライアント ID は、ブラウザに渡すための公開情報なので公開して問題ありません（クライアント シークレットは使っていません）。

### 4. 配る

- Windows の方：このフォルダ全体を ZIP にして渡します（`tests` フォルダと `記録` フォルダは不要です）。
- スマホの方：公開したアドレスを伝えます。

## できないこと・注意

- **Google フォト**のバックアップは確認できません（Google の仕様で、ほかのアプリから写真の一覧を見られないため）。Google フォトの場合は、Google フォトアプリの「空き容量を増やす」をお使いください。
- **iCloud 写真**には対応していません。
- OneDrive と同期しているフォルダ（Windows の「ピクチャ」が OneDrive に移っている場合など）は選べません。その場合は、エクスプローラーでフォルダを右クリック →「**空き容量を増やす**」で、クラウドに残したまま容量を空けられます。
- iPhone で写真を選ぶと、iPhone が自動で形式を変換することがあります。そのときは中身が一致しないため「まだクラウドにない」と判定されます（消さない側に倒れるので安全です）。
- Windows のゴミ箱の容量を超える大きなファイルは、Windows の仕様でゴミ箱に入らず削除されます（クラウドに同じものがあることは確認ずみです）。
- 名前ちがいの重複整理の対象は「まだクラウドにないもの」です。クラウドに保存ずみのものは、ふつうの削除の方で扱います。
- Google のログインは約 1 時間で期限が切れます。長い作業の途中で切れたときは「つなぐ」を押すだけで続きから再開できます。

## フォルダの中身

```
はじめる（ダブルクリック）.bat   Windows で起動するファイル
app/                              画面（スマホ用に公開するのはこの中身）
  index.html / style.css / icon.svg / manifest.webmanifest
  config.js                       ★ 設定（クライアント ID）
  js/main.js                      画面の流れ
  js/clouds.js                    Google ドライブ・OneDrive とのやりとり
  js/sources.js                   パソコン・スマホのファイルの読み方
  js/hash.js                      中身の指紋（MD5・QuickXorHash）の計算
  js/cache.js                     しらべ終わったファイルの指紋を覚えておく（次回を早くする）
  js/power.js                     充電・電池・画面スリープの見守り
server/server.ps1                 Windows 用の裏方（localhost だけで動きます）
tests/                            動作確認用
記録/                             削除・保存の記録（自動でできます）
```

## 動作確認（設定する方向け）

- **デモ**：アドレスの最後に `?demo=1` を付けて開くと、本物の写真やクラウドに一切さわらずに流れを試せます。
- **ファイルだけ本物の確認**：Windows で起動中に `http://localhost:8765/?demo=local` を開くと、クラウドは見本のまま、パソコンのファイルは本当に扱います（ゴミ箱に移ります）。試すときは、コピーした写真のフォルダでお試しください。
- **ハッシュ計算の検証**：`node tests/hash.test.mjs`（Microsoft 公開の QuickXorHash 実装・Windows 標準の MD5 と突き合わせます）
- **裏方の検証**：起動中に `node tests/server-api.test.mjs <テスト用フォルダ>`
